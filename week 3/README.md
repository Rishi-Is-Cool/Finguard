## Setup

### Backend
Run everything from the `week 3` directory — `backend/main.py` uses absolute
`backend.*` imports, so `uvicorn` must be able to see the package.

```bash
pip install -r backend/requirements.txt
cp .env.example .env
# Add GROQ_API_KEY (get one at console.groq.com)

uvicorn backend.main:app --reload --port 8000
```

Groq retires models periodically — `llama-3.1-8b-instant` no longer exists.
The default is now `openai/gpt-oss-20b`; override with `GROQ_MODEL` in `.env`.

### Frontend
```bash
cd frontend
npm install
npm run dev
# Open http://localhost:5173
```

### Generate sample data
`data/transactions.csv` (200 rows) is already checked in. To regenerate:

```bash
cd data && python generate_data.py && cd ..
```

## Fine-tuning (Days 15–17)

### Step 1: Build dataset
```bash
python data/build_dataset.py
# Creates data/fraud_dataset_train.json (408 examples)
#         data/fraud_dataset_test.json  (102 examples)
```

### Step 2: Run fine-tuning on Colab
```
1. Open colab.research.google.com
2. Runtime → Change runtime type → T4 GPU
3. Open notebooks/finetune_fraud_classifier.py
4. Copy each CELL_N into a Colab cell
5. Run cells 1-7 in order (~20 minutes)
6. Model pushed to HuggingFace Hub
```

### Step 3: Plug into backend
Point at the **merged** repo, not the LoRA adapter repo — `transformers`
cannot load bare adapters as a model.

```bash
# In .env (week 3 root):
FINGUARD_MODEL_NAME=your-username/finguard-fraud-classifier-merged
```

`classifier.py` preflights the hardware before loading. A merged 8B model needs
~16 GB of weights resident, so it requires a CUDA GPU with >=18 GB VRAM.
Without one it logs the reason and uses Groq instead — no 16 GB download, no
OOM. Override the check with `FINGUARD_FORCE_LOCAL=1` if you know better.

Either way the `ai_classifier` agent runs; `model_used` and `is_finetuned` in
its SSE payload (and in the UI) say which model actually did the work.

## Agent pipeline

```
POST /analyze  (SSE stream)
  1. extractor        pandas load, derive hour / weekday
  2. risk_classifier  4 deterministic rule tools -> risk_flags[], risk_score
  3. ai_classifier    fine-tuned (or Groq) model verdict on the top-N HIGH flags
  4. rag              CRAG: retrieve -> grade -> maybe rewrite -> generate
  5. report           LLM writes the compliance report
```

Step 3 is bounded by `FINGUARD_CLASSIFY_TOP_N` (default 5) over *distinct*
transactions, so one upload cannot fan out into hundreds of model calls. It is
wrapped so a classifier failure downgrades that step to `status: error` and the
rest of the run still completes. Its verdicts are fed into the report prompt.

Worth watching: the model routinely *disagrees* with the rules — on the sample
data it downgraded 4 of 5 rule-flagged HIGH transactions to MEDIUM. That
disagreement is the point of having both.

## CRAG — Corrective RAG (Day 19)

Standard RAG retrieves and generates. CRAG adds:
1. Grade each retrieved doc (1–5 relevance)
2. If avg score < 3.0 → rewrite query with LLM
3. Re-retrieve with new query
4. Generate only with high-quality context

This reduces hallucination in fraud rule citations.

## Known gaps (carried into Week 4)

- **The classifier runs on Groq, not the fine-tuned model, on CPU boxes.**
  The `ai_classifier` agent calls `classify_transaction_batch()` for real, but
  a merged Llama-3.1-8B is ~16 GB of fp16 weights. `classifier.py` preflights
  the hardware and falls back to Groq unless a >=18 GB CUDA GPU is present.
  The UI labels which model actually ran, so this is never silent.
- **The pushed LoRA adapter is empty.** `adapter_model.safetensors` in
  `RishiIsCool/finguard-fraud-classifier` is 40 bytes — an empty safetensors
  header. A real r=16 adapter over 7 modules x 32 layers is ~160-330 MB. Only
  the merged repo carries weights; re-verify that the merge captured training.
- **Dataset has label leakage.** `build_dataset.py` draws beneficiary names
  from three disjoint pools, one per risk level, so a model can score well by
  memorising "FastCash → HIGH". Accuracy from CELL_6 is not trustworthy.
  510 rows contain only 470 unique inputs, and 3 appear in both splits.
- **The event loop blocks.** Every `await asyncio.sleep()` in `/analyze` is
  cosmetic; pandas, Chroma, the CrossEncoder and all Groq calls are sync.
  One analysis freezes the whole server — single user only.
- **`build_crag(df)` runs per request**, re-loading the embedding and reranker
  models and rebuilding the vector store every time. Nothing is cached.
- **Nothing survives a restart** — `analysis_store` is an in-process dict and
  uploads go to a `tempfile.mkdtemp()`.
- **Week 2 features were dropped, not migrated**: LangGraph, the supervisor,
  human-in-the-loop review, and SQLite persistence are all gone. `thread_id`
  is still in the request model but is read nowhere.
- **RAG sources mix rules and transactions.** The CRAG corpus indexes fraud
  rules *and* every transaction row, so "Fraud Rules Referenced" in the UI can
  show raw transaction lines.
